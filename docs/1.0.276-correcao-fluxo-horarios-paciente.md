# v1.0.276 — Correção direta do fluxo de horários publicados

## Problema identificado

O médico já grava a disponibilidade real em `clinical_appointment_slots`, mas o Portal do Paciente passava os horários por `patient_portal_available_slots` antes de relacioná-los novamente aos planejamentos carregados. Isso criava uma segunda etapa de elegibilidade capaz de esconder uma vaga que já existia e pertencia ao mesmo médico/especialidade do acompanhamento.

## Correção

- A publicação médica continua usando `clinical_availability_series` + `clinical_appointment_slots` sem mudança estrutural.
- `/api/paciente/acompanhamentos` passa a buscar diretamente os slots futuros com status `Disponível` dos `doctor_id` presentes nos acompanhamentos ativos carregados para o paciente.
- A associação final continua sendo paciente/planejamento -> mesmo médico -> especialidade compatível.
- Especialidades compostas/legadas são comparadas por tokens (`[,]`, `;`, `/`, `|`) usando a normalização clínica já existente.
- A confirmação continua atômica pela RPC `book_patient_followup_slot`.
- Slots já publicados são lidos diretamente; não é necessário republicar horários.
- O botão `Minha disponibilidade` da Agenda Clínica foi renomeado para `Publicar horários`.

## Migração

Foi adicionada `20260819_000059_followup_booking_specialty_token_compatibility.sql`. Ela não cria tabela nem fluxo novo; apenas mantém a RPC de confirmação compatível com especialidades simples ou compostas, usando a mesma ideia de normalização da leitura do Portal.
