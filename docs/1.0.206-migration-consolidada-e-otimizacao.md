# Versão 1.0.206 — Migration consolidada e otimização

## Premissa confirmada
As migrations `20260803_000042` até `20260806_000048` não foram aplicadas no banco publicado.

## Migration final
As sete migrations ainda não executadas foram substituídas por uma única migration idempotente:

- `supabase/migrations/20260806_000049_consolidated_unapplied_changes.sql`

Ela aplica diretamente o estado final necessário para:

- encerramento diferido e proteção das ações do ponto;
- acesso centralizado e cadastro rápido de pacientes;
- edição e exclusão segura de planejamentos clínicos;
- arquivamento de profissionais desligados;
- histórico consolidado da Gestão de Leitos;
- visitas e alta exclusivamente médica.

Não são criadas tabelas intermediárias de eventos e visitas. A única tabela nova é `hospital_bed_history`.

## Otimizações

- salvamento do leito e histórico passou de duas requisições para uma RPC atômica;
- registro de visita usa uma RPC validada pelo servidor;
- cadastro rápido de paciente atualiza o estado local e deixa o Realtime apenas para conferência posterior, evitando uma leitura completa imediata adicional;
- índices parciais e compostos foram adicionados apenas para consultas realmente usadas;
- `ANALYZE` é executado ao fim da migration para atualizar as estatísticas do planejador do PostgreSQL;
- nenhum polling novo foi criado.

## Segurança e compatibilidade

- todas as RPCs validam sessão e vínculo com a equipe;
- operações de leitos são transacionais;
- dados antigos permanecem preservados;
- nenhuma tabela existente foi excluída;
- a migration é idempotente e usa `if not exists`/`create or replace`.

## Validação realizada

- revisão estática de todas as chamadas Supabase alteradas;
- verificação de que não permanecem referências às migrations substituídas;
- validação sintática dos arquivos TypeScript alterados com o compilador TypeScript;
- validação de JSON dos manifests;
- build completo não executado porque o pacote limpo não contém as dependências locais do projeto.
