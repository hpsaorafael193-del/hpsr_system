# HPSR System 1.0.228 — Correção de riscos da auditoria 1.0.227

## Objetivo
Corrigir exclusivamente os riscos confirmados na auditoria da versão 1.0.227, sem alterar regras clínicas, dados persistidos ou criar novas estruturas de banco.

## Alterações
- Corrigida a versão exibida em `DeveloperCreditsModal` para 1.0.228.
- Removida a opção de geração em PDF da interface futura de relatório da Agenda Clínica; PNG/imagem passa a ser o formato visual padrão, mantendo CSV e XLSX.
- `readSupabaseRows` não possui mais `select("*")` implícito; qualquer uso futuro precisa declarar colunas explicitamente.
- Exportação administrativa: fontes centrais usadas de forma estruturada pelo relatório passaram a selecionar somente as colunas efetivamente consumidas. Seções extras permanecem completas para preservar a finalidade de histórico integral do relatório.

## Estruturas reaproveitadas
- `clinical_records` continua sendo a fonte de verdade da vacinação.
- `getVaccinationCardDefinition` e `assignApplicationsToSlots` permanecem responsáveis por template, dimensões e encaixe dos registros.
- Nenhuma tabela, RPC ou fluxo paralelo foi criado.

## Compatibilidade
- Nenhuma migration.
- Nenhuma alteração de schema.
- Registros antigos de vacinação continuam sendo lidos pelo mesmo parser existente.
- Exportação administrativa mantém paginação e cobertura histórica.
- PDF continua aceito como tipo de anexo nos modelos que já permitem upload; a proibição desta versão refere-se à geração/exportação pelo HPSR.

## Otimização
- Eliminado `select("*")` implícito do helper genérico.
- Reduzido o volume de colunas transferidas nas fontes principais do relatório administrativo sem limitar as seções extras que dependem de conteúdo integral.

## Validações
- Revisão estática dos arquivos alterados e comparação com a base 1.0.227 realizada.
- Colunas explicitadas no relatório administrativo foram conferidas contra as migrations existentes.
- Busca por geração/exportação PDF não encontrou implementação de gerador PDF; as referências restantes a `application/pdf` pertencem aos tipos de anexos aceitos pelos modelos de exames.
- `npm run typecheck` foi tentado, mas não pôde validar o projeto porque as dependências locais estão incompletas no ambiente de execução.
- `corepack pnpm install --frozen-lockfile --ignore-scripts` foi tentado e falhou por indisponibilidade de acesso ao registry (`EAI_AGAIN registry.npmjs.org`).
- `npm run build` foi executado como tentativa de validação e falhou antes da compilação porque o binário `next` não está disponível nas dependências locais (`next: not found`).
- Portanto, **não há afirmação de build aprovado nesta entrega**.
