# v1.0.366 — Prontuário com leitura leve de registros clínicos

## Correção

O carregamento principal do Prontuário ainda extraía vários campos diretamente de `clinical_records.payload`, incluindo `examName`, `documentTitle`, médico, resumo e data do exame. Como os anexos/imagens também ficam dentro do mesmo JSONB, essa consulta podia exceder o `statement_timeout` e fazia o Prontuário manter um estado/cache sem eventos clínicos. O efeito visual era pacientes carregados, mas Exames, Documentos, Vacinas e demais contadores em zero.

A listagem principal agora consulta somente colunas leves: `id`, `patient_passport`, `record_type`, `created_at`, `is_confidential`, `history_title` e `history_doctor_name`. O payload completo continua sendo buscado apenas quando o usuário abre um exame/documento específico.

A chave de cache foi elevada para `v4` para invalidar estados antigos sem eventos. O realtime também prioriza os metadados leves.

Não houve nova migration nesta versão; os campos leves foram criados e preenchidos pela migration `20260920003615_optimize_clinical_history_metadata` da v1.0.365.
