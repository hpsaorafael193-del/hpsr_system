# v1.0.362 — Prontuário: exames e segurança de exclusões

## Contexto
A auditoria confirmou que os exames permaneciam no Supabase e voltaram a aparecer no Prontuário sem restauração manual. Portanto, não houve alteração de conteúdo dos exames nem rotina de recuperação em massa.

## Correções aplicadas
- `clinical_records` deixou de usar uma política `FOR ALL` para toda a equipe.
- Leitura, inserção e atualização continuam disponíveis à equipe autenticada conforme `is_hpsr_staff()`.
- Exclusão de registro clínico passou a exigir `is_access_admin()`.
- Foi criada `clinical_record_deletion_audit`, que preserva o snapshot completo de cada registro excluído, passaporte, tipo, usuário e data.
- Toda exclusão de registro clínico gera uma atividade em `system_activities`.
- `delete_patient_registry_cascade()` agora exige `is_access_admin()` antes de apagar qualquer dado.
- A exclusão de paciente gera atividade administrativa e as exclusões de registros clínicos durante a cascata também passam pelo trigger de auditoria.
- A interface do Prontuário só exibe os botões de exclusão para Diretora, Vice Diretor, Vice Diretor / Dev ou Administrador do Sistema.

## Observação
A lógica de carregamento/exibição dos exames não foi alterada nesta versão porque os exames voltaram a aparecer e a leitura do Supabase foi validada com o perfil administrativo atual.
