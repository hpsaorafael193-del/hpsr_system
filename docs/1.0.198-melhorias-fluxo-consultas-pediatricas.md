# Versão 1.0.198 — Melhorias no fluxo de consultas pediátricas

## Escopo
- Correção do erro de build causado pela ausência do tipo `FormEvent`.
- Ajuste do Portal do Paciente para o fluxo pediátrico solicitado.

## Fluxo do responsável
- O responsável informa manualmente nome, passaporte, idade e vínculo da criança.
- O sistema compara o passaporte e o nome com o Prontuário.
- Se encontrar correspondência exata, prepara uma solicitação de vínculo.
- Se não encontrar, cria o prontuário infantil e mantém o vínculo pendente.
- A criança não recebe login próprio.
- Nenhum dado clínico é liberado enquanto o vínculo estiver pendente.
- Solicitações pendentes aparecem no Portal com status claro.

## Fluxo médico
- A solicitação aparece no gerenciamento de responsáveis do prontuário infantil.
- O médico confere os dados e confirma o vínculo em um único botão.
- Também pode encerrar ou manter o vínculo sem liberar acesso.
- O sistema preserva o prontuário já existente e bloqueia conflito de passaporte com nome diferente.

## Desempenho e segurança
- Nenhum polling novo.
- A sessão carrega vínculos pendentes junto das informações já utilizadas no Portal.
- Vínculos pendentes usam `portal_access = false` e não são retornados pela função de pacientes acessíveis.
- Nenhuma migração foi necessária porque a tabela já suporta o status `pending`.
