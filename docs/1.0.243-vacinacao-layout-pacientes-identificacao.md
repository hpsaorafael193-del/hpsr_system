# HPSR System 1.0.243 — Vacinação: layout, pacientes e identificação automática

## Objetivo
Ajustar a aba de Vacinação sobre a base 1.0.242 para alinhar a coluna de preview/histórico ao card lateral, melhorar a distribuição do formulário, exibir todos os pacientes do prontuário no seletor e identificar automaticamente o modelo da caderneta quando houver dados cadastrais suficientes.

## Alterações
- Card lateral ampliado de 390px para 470px em desktop amplo.
- Grupo/modelo adulto e vacina/dose foram distribuídos lado a lado quando aplicável, reduzindo a altura do formulário.
- A coluna direita passa a ocupar toda a altura do grid em desktop, com preview flexível e histórico fixado no rodapé da coluna.
- O histórico mantém altura própria e rolagem interna.
- A lista visual de pacientes deixou de limitar a exibição a 8 registros: todos os pacientes retornados pela fonte institucional ficam disponíveis dentro de uma lista com rolagem própria.
- A lista exibe contador de resultados e, quando disponível, idade e sexo cadastral.
- Seleção de paciente cadastrado identifica automaticamente Infantil/Adulto/Idoso pela idade; quando necessário, a idade é calculada pela data de nascimento usando a data civil brasileira.
- Para pacientes adultos, o modelo Masculino/Feminino é selecionado automaticamente quando o sexo está cadastrado.
- Gestante permanece seleção clínica manual; sexo feminino não ativa automaticamente o modelo gestante.

## Prontuário
- Adicionado campo cadastral opcional `Sexo`, limitado a `Masculino` ou `Feminino`.
- Cadastro e edição de pacientes passam a permitir preencher esse campo.
- A visão geral do prontuário passa a exibir o sexo quando informado.
- A fonte compartilhada de pacientes passa a transportar também `birth_date` e `sex`.

## Migration
- `supabase/migrations/20260811_000052_patient_sex_and_registry_listing.sql`
- Adiciona `patient_registry.sex` de forma não destrutiva.
- Recria `list_patient_registry_staff()` para retornar também `birth_date` e `sex`.
- Nenhum dado antigo é apagado; registros existentes ficam com sexo nulo até serem atualizados.

## Compatibilidade
- Pacientes antigos continuam funcionando normalmente.
- Se sexo não estiver preenchido, o modelo adulto continua ajustável manualmente.
- Não houve alteração nos registros clínicos, templates das cadernetas ou geração PNG.

## Validação
- Revisão estática dos fluxos alterados realizada.
- O build só pode ser declarado aprovado se `npm run build`/`pnpm run build` concluir com dependências instaladas.
