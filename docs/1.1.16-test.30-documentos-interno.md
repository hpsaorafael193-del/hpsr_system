# HPSR System v1.1.16-test.30 — Documentos, Exames e Interno

## Escopo

Esta rodada consolida a proposta de Documentos/Exames/Laudos dinâmicos e amplia a área Interno, sem iniciar o acompanhamento pediátrico.

## Documentos

- O navegador deixa de ser fonte de persistência clínica: não há `localStorage`/`sessionStorage` para rascunho clínico da aba Documentos.
- Novos documentos são persistidos como dados estruturados em `clinical_records` (`schemaVersion: 2`).
- A pré-visualização é renderizada dinamicamente no React/HTML; PNG só é materializado ao clicar em **Baixar PNG**.
- O histórico ganhou **Editar**, permitindo reabrir um documento salvo no editor.
- Salvar uma edição de um documento já liberado não altera silenciosamente a versão do paciente.
- **Salvar e atualizar Portal** publica explicitamente a versão atual.
- Recolher/liberar continua usando o controle de confidencialidade do registro.
- Os 3 documentos históricos já liberados foram congelados em `releasedSnapshot`, preservando a versão que já estava pública, inclusive a prévia legada existente.

## Exames e laudos

- Novos exames são salvos como payload estruturado (`examKind: structured-exam`) sem gerar/salvar PNG durante o salvamento.
- A pré-visualização passou a usar `RenderedExamPageView`, sem converter automaticamente a tela em PNG.
- O Canvas existe apenas no fluxo explícito de **Baixar PNG**, usando `canvas.toBlob()`.
- A liberação de novos exames usa `set_clinical_record_confidentiality`, que agora captura `releasedSnapshot` tanto para Documento quanto para Exame.
- Os 97 exames históricos atualmente liberados continuam no formato legado e são lidos pelo Portal pelo fallback já existente. Eles não foram duplicados em snapshot nesta rodada para evitar replicar em massa as 171 prévias antigas embutidas; qualquer nova liberação/reliberação passa a criar snapshot estruturado.

## Portal do Paciente

- Para Documento/Exame com `releasedSnapshot`, o Portal lê exclusivamente a versão liberada.
- Edições internas posteriores não alteram título, médico, conteúdo ou data de atualização visível até nova publicação.
- Registros históricos sem snapshot continuam compatíveis pelo payload legado.

## Interno

A aba Interno recebeu a seção **Documentos** para Diretora e Vice Diretor / Dev:

- busca por paciente, passaporte ou título;
- conferência de status **SIGILO / PORTAL**;
- correção apenas de metadados administrativos de Documento, com justificativa;
- liberação ou recolhimento de Documento/Exame com justificativa;
- registro de auditoria em `system_activities`;
- nenhum editor de conteúdo clínico foi colocado no Interno.

RPCs administrativos novos:

- `hpsr_internal_correct_record_metadata(text,text,text)`
- `hpsr_internal_set_record_visibility(text,boolean,text)`

As RPCs são `SECURITY DEFINER`, validam `hpsr_can_access_internal()` e tiveram `EXECUTE` removido de `public`/`anon`, ficando disponível para `authenticated` com a autorização interna aplicada dentro da função.
